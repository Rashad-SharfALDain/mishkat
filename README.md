# مؤسسة مِشكاة التربوية والتعليمية (Mishkat Educational Platform)
> **"نبني العلم... ونصنع الشخصية... ونَصنع أثرًا"**  
> موقع إلكتروني ومنظومة تسجيل متكاملة لمؤسسة تعليمية وتربوية ذات رسالة خيرية وقفية تُعنى ببناء الشباب والقيادات الواعدة ابتداءً من الصف الأول الثانوي وما بعده.

---

## 🌟 نظرة عامة على المشروع (Project Overview)

تم بناء الموقع والمنظومة الإلكترونية بالكامل لدعم اللغة العربية وتجربة المستخدم من اليمين إلى اليسار (**True Arabic RTL**)، مع هوية بصرية ملكية رصينة تجمع بين الأخضر الزمردي العميق (**Deep Emerald**)، والذهب الدافئ (**Warm Gold**)، وخلفيات العاج الناعمة (**Ivory & Off-white**)، والخطوط العربية الحديثة المعتمدة (**Cairo & Amiri**).

الموقع ليس قالباً شكلياً؛ بل هو تطبيق متكامل حقيقي (**Production-Ready Web Application**) يشتمل على:
1. **واجهة عامة غنية وتفاعلية (Public Institutional Experience)**
2. **منظومة تسجيل إلكترونية متعددة المراحل (Multi-Step Registration Stepper)** مع توليد فوري لأرقام الطلبات المرجعية المعتمدة (`APP-2026-XXXXX`).
3. **لوحة تحكم إدارية متكاملة (Secure Admin Dashboard)** لمتابعة الطلبات، وفرز المتقدمين، وتحديث الحالات، وتدوين الملاحظات التقييمية الداخلية، وتعديل إعدادات المؤسسة والرسوم.
4. **قاعدة بيانات علائقية كاملة (Relational SQLite Database)** مطابقة لأدق المعايير الهندسية ومعززة بحفظ البيانات تلقائياً على القرص (`data/institution.sqlite`).
5. **منظومة أمان وحماية للبيانات والخصوصية** تحمي معلومات القُصّر وأولياء الأمور مع تشفير كلمات المرور وتأمين الجلسات عبر توكنات JWT وحدود معدلات الطلب (Rate Limiting).

## 🚀 طريقة تشغيل المشروع (How to Run the Project)

### المتطلبات الأساسية
- **Node.js** (الإصدار 18 فما فوق، تم التثبيت والتجهيز بنجاح).
- **npm** (الإصدار 9 فما فوق).

### التشغيل الفوري (Development & Production Server)

1. **تشغيل الخادم والتطبيق فوراً (Both API + Built Frontend on Port 5000):**
   ```bash
   npm start
   ```
   أو
   ```bash
   npx tsx server/src/index.ts
   ```
   سيتم تشغيل الخادم على: `http://localhost:5000/`.

2. **تشغيل خادم التطوير التفاعلي للواجهة الأمامية (Vite HMR):**
   ```bash
   npm run dev:client
   ```
   سيعمل خادم Vite على `http://localhost:3000` مع توجيه تلقائي لاستدعاءات `/api` إلى الخادم الخلفي.

3. **إعادة بناء حزمة الإنتاج (Production Build):**
   ```bash
   npm run build
   ```

4. **تشغيل الفحص الآلي الشامل لجميع الوظائف (Integration Test Suite):**
   ```bash
   node test_system.js
   ```

## 🔐 آلية المصادقة وحساب الإدارة الآمن (Secure Admin Authentication)

* **رابط الوصول المباشر:** افتح الموقع على `http://localhost:5000/` ثم انقر على **"دخول الإدارة"** في أعلى الترويسة، أو استخدم الرابط المباشر `http://localhost:5000/#admin`.
* **إعداد بيانات الحساب:** تُضبط بيانات الدخول الإدارية حصرياً عبر متغيرات البيئة في ملف `.env` (وليس داخل الكود المصدري):
  * `ADMIN_EMAIL`: البريد الإلكتروني المعتمد للمسؤول.
  * `ADMIN_INITIAL_PASSWORD`: كلمة المرور المؤقتة للتأسيس الأولي فقط.
* **إلزامية تغيير كلمة المرور:** يفرض النظام أمنياً على المشرف تغيير كلمة المرور وتعيين كلمة مرور خاصة وقوية فور أول عملية تسجيل دخول ناجحة، ولا يُسمح بالوصول إلى لوحة التحكم إلا بعد إتمام هذه الخطوة بنجاح.

## 🗄️ معمارية قاعدة البيانات العلائقية (Database Schema)

تتألف قاعدة البيانات من 8 كيانات علائقية مترابطة مطابقة لمتطلبات وثيقة العمل:

1. **`users`**: حسابات مسؤولي النظام ومشرفي القبول (كلمات مرور مشفرة بـ `bcryptjs`، وتوزيع الأدوار).
2. **`applicants`**: سجلات الطلاب المتقدمين الكاملة، وأرقام الطلبات المرجعية المفرزة، ومعلومات ولي الأمر، والدافعية، والملاحظات الداخلية، والحالات الخمس:
   - `جديد` (New)
   - `قيد المراجعة` (In Review)
   - `مقبول` (Accepted)
   - `مرفوض` (Rejected)
   - `مكتمل` (Completed)
3. **`programs`**: المسارات التعليمية الأربعة (العلوم الشرعية، العلوم والمعارف، بناء الشخصية، القيادة) وموضوعاتها الإثرائية.
4. **`applications_programs`**: جدول الربط المتعدد بين الطلبات والمسارات المختارة.
5. **`payments`**: هيكل المساهمات المالية والرسوم الرمزية وتتبع حالات الإعفاء والكفالات.
6. **`content`**: المحتوى النصي القابل للتخصيص.
7. **`faq`**: بنك الأسئلة الشائعة وتصنيفاتها وترتيب ظهورها.
8. **`contact_messages`**: رسائل الاستفسار الواردة عبر نموذج الاتصال، وحالات التعامل معها (`new`، `read`).
9. **`settings`**: مخزن الإعدادات الديناميكية للمؤسسة (الاسم، حالة القبول، الرسوم، الصفوف المؤهلة، قنوات الاتصال، الآيبان).

## 🛠️ كيف تعدل بيانات المؤسسة وإعدادات القبول؟ (Modifying Settings)

لا يتطلب تعديل بيانات المؤسسة أو فتح/إغلاق التسجيل أو تعديل الرسوم أي تعديل في الأكواد البرمجية:
1. قم بتسجيل الدخول إلى **لوحة تحكم الإدارة**.
2. انتقل إلى تبويب **"إعدادات المؤسسة"**.
3. يمكنك تعديل:
   - **اسم المؤسسة وشعارها**.
   - **حالة التسجيل:** تحويلها فورياً بين `مفتوح` و`مغلق`.
   - **قيمة المساهمة المالية:** تعديل المبلغ الرمزي والحد الأقصى (الافتراضي 500 ريال بحد أقصى 1000 ريال مع شرح إعفاءات صندوق المنح).
   - **الصفوف الدراسية المؤهلة** ومواعيد انتهاء التقديم.
   - **أرقام الهواتف والواتساب والعنوان ومواعيد العمل**.
   - **اسم الحساب البنكي ورقم الآيبان (IBAN) المعتمد**.
4. انقر على **"حفظ وتطبيق التغييرات"** ليتم تحديث الموقع فورياً لدى كافة الزوار.

## 🛡️ الأمان وحماية خصوصية بيانات الطلاب (Security & Privacy)

- **حماية بيانات القُصّر:** لا تظهر أي بيانات حساسة للطلاب أو أرقام هواتفهم أو عناوينهم في أي صفحة عامة.
- **تأمين نقاط النهاية الإدارية:** مسارات `/api/admin/*` محمية بالكامل بواسطة وسيط المصادقة `requireAuth` الذي يفحص صلاحية التوكن المشفر `Bearer JWT`.
- **حماية النماذج ضد الإغراق والسبام (Anti-Spam Honeypot & Rate Limiting):** يحتوي نموذج التواصل على حقل وهمي مخفي لاكتشاف روبوتات السبام، مع تطبيق وسيط `rateLimiter` لمنع الهجمات المتكررة.
- **ترويسات أمان متقدمة:** تطبيق ترويسات `X-Content-Type-Options: nosniff` و`X-Frame-Options: DENY` و`X-XSS-Protection`.

## 🎓 المرحلة الثانية — الإصدار الفرعي 2.1: بوابة الطالب والمنظومة التعليمية (Phase 2.1: Student Portal)

في هذه المرحلة، تم تحويل المنظومة من مجرد (موقع تعريفي + تسجيل + إدارة) إلى **منظومة إدارة مؤسسية وبوابة تعليمية متكاملة للطلاب المقبولين**، مع الحفاظ الكامل على كافة وظائف الإصدار الأول (V1) دون أي كسر أو حذف.

### 1. مبدأ انتقال البيانات (Data Transition Principle)
* **المتقدم ليس طالبًا تلقائيًا:** يمر الطالب بدورة حياة واضحة:
  $$\text{متقدم (Applicant)} \longrightarrow \text{مقبول (Accepted)} \longrightarrow \text{اعتماد المشرف وإنشاء حساب طالب} \longrightarrow \text{طالب مقيد (Enrolled Student)}$$
* لا يُسمح بإنشاء حساب طالب لأي متقدم حالته "جديد" أو "قيد المراجعة" أو "مرفوض".
* يتم إنشاء الحساب من قِبل إدارة القبول والتسجيل بنقرة واحدة بعد المقابلة والاعتماد.

### 2. الرقم الأكاديمي الدائم (Unique Student Number)
* يتم توليد رقم أكاديمي فريد وتسلسلي ودائم لكل طالب بصيغة: `STU-2026-XXXXX` (مثال: `STU-2026-00001`).
* الرقم الأكاديمي دائم، لا يتكرر، ولا يتأثر بموقع السجل أو إعادة تشغيل الخادم، ويمكن للطالب استخدامه لتسجيل الدخول مباشرة.

### 3. تجربة دخول الطالب وتأمين الحساب (Student Login & First-Login Password Change)
* **فصل كامل بين البوابات:** تمييز واضح بين **"دخول الطالب"** و **"دخول الإدارة"** في الترويسة والقوائم الجوالة.
* **رابط الوصول المباشر لبوابة الطالب:** `http://localhost:5000/#student`
* **كلمة المرور المؤقتة:** يُنشئ النظام كلمة مرور تأسيسية معقدة ومؤقتة تُسلم للطالب، ويفرض النظام عليه فور تسجيل الدخول الأول تعيين كلمة مرور شخصية خاصة وقوية (أحرف كبيرة وصغيرة وأرقام) قبل الدخول للبوابة.

## 👨‍👩‍👧‍👦 المرحلة 2.2: بوابة أولياء الأمور (Phase 2.2 Parent / Guardian Portal)

تم تدشين بوابة أولياء الأمور كبوابة تربوية متخصصة ومستقلة، تهدف إلى إشراك ولي الأمر في مسيرة بناء الطالب ومتابعة تحصيله وانضباطه في بيئة مؤمنة بالكامل:

### 1. الكيانات وقواعد البيانات (Parent Database Architecture)
تم الحفاظ التام على قاعدة البيانات وتطبيق هجرة تراكمية آمنة بإضافة الجداول الآتية:
* **جدول أولياء الأمور (`parents`):**
  * `id`: المعرف الفريد لولي الأمر (UUID).
  * `user_id`: المفتاح الأجنبي المرتبط بحساب المستخدم المعتمد في جدول `users`.
  * `full_name`: الاسم الثلاثي لولي الأمر.
  * `relationship`: الصفة المعتمدة (`أب`، `أم`، `ولي أمر شرعي`).
  * `phone`: رقم الهاتف المعتمد (يُستخدم كمعرف للدخول والتواصل).
  * `email`: البريد الإلكتروني.
  * `address`: عنوان الإقامة أو المدينة.
  * `national_id`: رقم الهوية الوطنية/الإقامة (إن وجد).
  * `status`: حالة الحساب (`نشط`، `غير نشط`).
  * `created_at`, `updated_at`: الطوابع الزمنية.

* **جدول علاقة ولي الأمر بالطالب (`parent_student`):**
  * علاقة متعدد-إلى-متعدد (Many-to-Many capable) تدعم وجود أكثر من ابن لولي الأمر الواحد، وإمكانية وجود أكثر من ولي أمر معتمد للطالب الواحد.
  * `id`: معرف علاقة الارتباط.
  * `parent_user_id`: معرف المستخدم لولي الأمر.
  * `student_id`: معرف الطالب المقيد.
  * `relationship`: صلة القرابة بهذا الابن تحديدًا.
  * `is_primary`: مؤشر الولي الأساسي (1 أو 0).
  * `status`: حالة الرابط (`active` أو ملغى).
  * `created_at`: تاريخ توثيق الارتباط.

### 2. دور المستخدم وصلاحيات الدخول (Parent Role & Auth)
* إضافة الدور `parent` إلى منظومة الصلاحيات، مع الحفاظ التام والكامل على صلاحيات `admin` و `student`.
* **فصل مرئي للبوابة:** تمييز واضح بين **"دخول ولي الأمر"** و **"دخول الطالب"** و **"دخول الإدارة"** في الترويسة العلوية والقوائم المتنقلة.
* **رابط الوصول المباشر لبوابة ولي الأمر:** `http://localhost:5000/#parent`
* **آلية تفعيل الحساب:** تُنشأ الحسابات وتُفعل بآلية إدارية معتمدة من شؤون الطلاب (لا يوجد تسجيل عشوائي مفتوح للعامة)، ويُسلّم ولي الأمر كلمة مرور مؤقتة يُجبر على تغييرها إلى كلمة سر قوية خاصة به في أول تسجيل دخول.

### 3. أقسام بوابة ولي الأمر (Parent Portal Views)
* **الرئيسية (Dashboard):**
  * بطاقة ترحيبية باسم ولي الأمر وعدد الأبناء المرتبطين.
  * محدد الطالب النشط (`اختر الطالب`) في حال وجود أكثر من ابن مسجل، وتصفية كافة الإحصائيات والمعلومات التابعة له.
  * مؤشرات ملخصة للمسار، حضور وانضباط الابن، وحالة التقييمات القيمية، وآخر الإعلانات.
* **أبنائي وملف الابن (Child Profile):**
  * عرض البيانات الأكاديمية المعتمدة للابن المحدد: الاسم، الرقم الأكاديمي، المسار التعليمي، الصف الدراسي، المستوى، المدرسة، وتاريخ القبول.
  * **الخصوصية التامة:** عزل وحجب الملاحظات الداخلية وسجلات لجان القبول والمشرفين نهائيًا عن ولي الأمر.
* **حضور وانضباط الابن (Attendance Foundation):**
  * تأسيس البنية الهيكلية لرصد الحضور (نسبة الالتزام، أيام الحضور، الغياب بعذر، الغياب بدون عذر).
  * **بدون بيانات زائفة:** يظهر بوضوح وإشعار شفاف: `(سيتم تفعيل متابعة الحضور قريبًا)` تمهيدًا للمرحلة 2.3.
* **التقدم التعليمي والقيمي (Educational Progress):**
  * محاور البناء الخمسة في مؤسسة مِشكاة: (العلوم الشرعية، العلوم والمعارف، بناء الشخصية، القيادة، والأنشطة والمبادرات).
  * توضيح تربوي بأن التقييمات التراكمية تُنشر فور اعتمادها رسميًا من المشرفين في المرحلة القادمة.
* **أنشطة ومهام الابن (Activities):**
  * استعراض مشاريع وواجبات الابن وتواريخ استحقاقها وحالات تسليمها.
  * **صلاحية للقراءة فقط (Read-Only):** يحق لولي الأمر معاينة إجابة الابن وملاحظات المشرف دون أي إمكانية للتعديل أو العبث بسجلات الطالب.
* **إعلانات أولياء الأمور (Announcements):** التعاميم والرسائل الرسمية الموجهة لأولياء الأمور.
* **التقارير الدورية (Reports):** بطاقة تأسيسية شفافة تشرح خطة التقارير الفصلية المعتمدة في المرحلة 2.3.
* **ملفي الشخصي (Parent Profile):** إمكانية تعديل بيانات الاتصال فقط (رقم الهاتف، البريد، العنوان)، وتغيير كلمة المرور الشخصية، مع حظر تعديل العلاقات أو الحالات الأكاديمية.

### 4. النموذج الأمني وحماية الخصوصية (Security Model & IDOR Prevention)
* **الحماية الصارمة من ثغرات المعرف المباشر غير الآمن (Anti-IDOR):**
  * يعتمد الخادم دائمًا على هوية المستخدم الموثقة في رمز الجلسة `req.user.id`.
  * عند طلب أي مورد خاص بطالب `/api/parent/students/:id/*`، يتحقق الخادم أولاً من جدول `parent_student`؛ فإذا لم يكن الطالب مرتبطًا بولي الأمر، يُرد الطلب فورًا بـ `HTTP 403 Forbidden`.
* **عزل كامل بين أولياء الأمور:** لا يمكن لولي الأمر أ الاطلاع على أي معلومة تخص ابن ولي الأمر ب.
* **العزل الصارم للأدوار (RBAC):** يُحظر على توكن ولي الأمر الوصول لأي من واجهات الإدارة `/api/admin/*` أو واجهات بوابة الطالب `/api/student/*` (HTTP 403).
* **الإلغاء الفوري للصلاحية:** بمجرد فك ارتباط طالب من ولي أمره عبر الإدارة، تُلغى قدرة ولي الأمر على الوصول لمعلومات ذلك الطالب فورًا.

### 5. إدارة أولياء الأمور في لوحة الإدارة (Admin Parent Management)
إضافة تبويب **"أولياء الأمور"** في لوحة تحكم الإدارة يدعم:
* استعراض قائمة أولياء الأمور المعتمدين مع عداد الأبناء المرتبطين.
* البحث الفوري بالاسم، رقم الهاتف، البريد الإلكتروني، أو السجل المدني.
* التصفية بحسب حالة الحساب (`نشط`، `غير نشط`).
* تفاصيل ولي الأمر وقائمة الأبناء المرتبطين به مع خيار فك الارتباط.
* إضافة وتفعيل ولي أمر جديد وتوليد بيانات دخول مؤقتة فورية مع إمكانية النسخ.
* ربط طالب مسجل بولي الأمر مع تحديد صفة القرابة وما إذا كان الولي الأساسي.
* إعادة تعيين كلمة المرور لولي الأمر وتفعيل خيار إجبار التغيير في أول دخول.
